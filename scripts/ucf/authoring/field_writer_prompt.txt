## Fields (CSV columns): id,statement,why_asked,how_to_ask,question,expected_evidence,good_looks_like,test,baseline_risk,applicability,control_type,frequency,key_settings
- statement: who (the owner role or a named role), does what, when (how often or on what trigger), how, why, proof. 2 to 4 sentences, active voice, one goal. Framework-neutral. The goal in the skeleton is the single goal; the statement expands it, it does not widen it.
- why_asked: one or two sentences, the failure this prevents, written for a consultant.
- how_to_ask: plain direction for putting it to the client, ending with one example probe in quotes.
- question: the client-facing question. One obligation, one sentence, ends with exactly one question mark, answerable on the scale fully / partially / planned / not / not applicable. Start like "Does your organization...". No "and" joining two obligations, no semicolons, no control codes, no framework names. If the control has several parts, ask about the whole control's single goal, not a list.
- expected_evidence: artifact names in the client's words (policy, register, export, report, sign-off record), joined with semicolons, and the period to cover ("last 12 months", "last two cycles"). Seed from the existing evidence requests but reword them: never name a framework, standard or clause number.
- good_looks_like: what a fully implemented answer contains, 2 to 3 sentences.
- test: what to sample and what a pass looks like (sample size and period, then the pass condition). Seed from the signed criteria in the brief; rewrite in your own words; one test per control.
- baseline_risk: one sentence, what happens if absent.
- applicability: when the control applies, if conditional (for example "Applies if the organization develops software in house"); empty if always.
- control_type: preventive, detective or corrective (choose one).
- frequency: one of continuous, per_event, monthly, quarterly, annual, ad_hoc.
- key_settings: numbers and timeframes the control states, as `base: setting | base: other setting`. Layer is `base` for anything you set here. If you write ANY number with a unit (hours, days, months, years, %, "twice a year") anywhere in the other fields, the same wording must appear in key_settings. Prefer no numbers: use "on a defined cycle" and put the cycle in key_settings only if the sources state one. Do not invent legal deadlines. Empty if none.
