## Goal

Audit findings F-B4, F-F6 and F-F25 (`tasks/2026-10-13-content-audit.html`, search each id; plan row 2.3 and §5.3 in `docs/plans/2026-10-13-001-single-track-implementation-plan.md`).

- Today a framework score is labelled with outcome words ("84% (Compliant)"). A board reads that as a certification claim while 17 high-risk gaps are open.
- The thresholds are described four different ways, and a score of 79.6 prints "80%" beside the band below 80.

After this WP:
- Every framework and domain score uses the readiness band, `vocabulary.SCORE_BANDS` and `score_band()`, which already exist (WP 1.1).
- The band is computed from the unrounded score and printed with one decimal.
- A framework band always sits beside that framework's own critical and high gap counts.
- One sentence describes the thresholds everywhere.

## Decisions (Saqlain: plan Q2 on 13 Oct; the rest confirmed 15 Oct)

| # | Decision | Value |
|---|---|---|
| D1 | Bands | `Not ready` (below 40), `Partly ready` (40 to below 60), `Mostly ready` (60 to below 80), `Ready` (80 and above). Thresholds and scoring math do not change. Use `vocabulary.score_band(unrounded_score)`; never band a rounded score. |
| D2 | Score format | One decimal wherever a band word or threshold is beside a score, in PDF, HTML board report, PPTX, XLSX and DOCX: `79.6%`. Use one shared formatter in `vocabulary.py`, e.g. `score_text(score) -> "79.6%"`. Score rings and bars with no band word beside them may keep their current format, but if in doubt use the formatter. |
| D3 | Framework headline line | Exactly: `{target}: {band} ({score}). {gaps}` for example `Readiness for ISO 27001 certification: Mostly ready (79.6%). 2 critical and 9 high gaps open.` The gaps part: both zero gives `No critical or high gaps open.`; otherwise `{c} critical and {h} high gaps open.` (`gap` singular only when c + h == 1). Counts are that framework's own open gaps by risk level, not the assessment total. |
| D4 | Target phrases | One map in `vocabulary.py`, keyed by framework id: `dpdpa` "Readiness for DPDP Act obligations"; `iso27001` "Readiness for ISO 27001 certification"; `nist_csf` "Readiness against NIST CSF 2.0 target profile"; `gdpr` "Readiness for GDPR obligations"; `hipaa` "Readiness for HIPAA Security Rule safeguards"; `pci_dss` "Readiness for PCI DSS v4.0 assessment". Domain and chapter lines use the band word only, no target: `Mostly ready (79.6%)`. |
| D5 | Threshold description | One helper in `vocabulary.py`, generated from `SCORE_BANDS`, used by the PDF methodology, the board report legend, the PPTX domain-slide line and "How to read" slide, and the XLSX Definitions sheet. Exactly: `Ready: 80% and above. Mostly ready: 60% to below 80%. Partly ready: 40% to below 60%. Not ready: below 40%. The band uses the exact score; scores are shown to one decimal.` A list form (one band per line, same words) is fine where the layout is a list. |
| D6 | Already-issued reports | Wave 1 decision: re-exports of issued snapshots use the new wording. Renderers (PDF, PPTX, XLSX, DOCX, HTML) derive the band from the stored numeric score with `score_band()`. They never print a stored rating string. Stored issued PDF bytes are never re-rendered (unchanged). Do **not** bump `DOCUMENT_SCHEMA_VERSION`. Old v1 to v3 documents must render with new words. |
| D7 | Stored strings | `Report.framework_scores` and `chapter_scores` JSON already hold old strings. Do not migrate them. Every reader re-bands from the score. New analyses may store the new band word in `overall_rating` / `rating` (keeps the API shape), but no display reads it. |
