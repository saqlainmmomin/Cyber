## Decisions

| # | Decision | Value |
|---|---|---|
| D1 | Backfill rule for `assessments.selected_frameworks` | NULL becomes `["dpdpa"]` (every multi-framework creation path has always written the list explicitly, so NULL is legacy DPDPA by construction). Invalid JSON, a non-list, an empty list, or a framework id outside the six known ids (`dpdpa`, `iso27001`, `gdpr`, `hipaa`, `nist_csf`, `pci_dss`; check the real ids in `app/frameworks/registry`) is **refused with a report**, never defaulted. Freeze the id list as a literal inside the migration. |
| D2 | Backfill rule for `desk_review_findings.framework_id` and `gap_items.framework_id` | NULL becomes `'dpdpa'` only when the owning assessment's (post-backfill) framework list contains `dpdpa`. A NULL row under an assessment without `dpdpa` is ambiguous: refuse with a report. |
| D3 | Preflight | The migration first counts null and invalid rows per table and per rule, and writes the counts into the exception message when it refuses. The preflight is a plain function so a test can call it without running Alembic. |
| D4 | Downgrade | Raises `RuntimeError` like `8b2d5f7e1c34`. No attempt to re-null. |
| D5 | NOT NULL | Do not add NOT NULL constraints or model `@validates` that reject None. SQLite batch rewrites are risky and the plan does not ask for it. The readers stop defaulting; the migration guarantees the data. |
| D6 | `Assessment.frameworks` | Returns the stored list. It **raises** `ValueError` for NULL, unparseable or empty storage instead of returning `["dpdpa"]`. Every seed and test writer sets `selected_frameworks` explicitly. If making tests explicit would touch more than about 25 test files, stop and list them. |
| D7 | Upload categories | New function (suggested `upload_categories(framework_ids)` in `app/services/document_categories.py`): the assessment's frameworks' categories plus `other`. The nine legacy categories appear only when `dpdpa` is in scope. **`document_categories()` itself stays byte-for-byte unchanged**, because the judge prompt and its fingerprints read it (`app/services/grounding/judge.py:436, 595, 611, 623`; `tests/test_p6_1b_framework_batching.py:152`). Stored category strings stay valid (display falls back to the raw string). |
| D8 | Initiative text | `_build_approach` (`app/services/scoring.py` about 567 to 589) takes the member's framework. DPDPA members keep today's privacy wording exactly. Other frameworks get neutral wording built from the cluster name and its requirement titles (no DPO, privacy counsel, DPIA or consent text). `generate_initiatives` (curated, DPDPA-only, `analysis.py` about 495) and its names, clusters and prefix fallback are untouched. |
| D9 | Section refs (C6) | One helper in `app/services/vocabulary.py` (it already hosts `display_reference` and `reference_with_framework`). Both `conclusions.html` and `review_queue.html` call it, plus `partials/review_finding_card.html`, `components/workpaper_entry.html` and `web.py` about line 3666. Both screens must keep showing what they show today for DPDPA, ISO and NIST rows (no visible change). The "hard-coded DPDPA refs" claim in the 7 Oct review is stale; verify and say so in Results. |
