## Scoping decisions
1. **Error pages:** as the brief says (404/500/catch-all in `app/main.py`, `pages/error.html`, reference code logged with path and exception class, JSON stays JSON for `/api/...` and `Accept: application/json`, engagement-scoped 404 never confirms the engagement exists). States `page`, `engagement`, `error`, `down`, `upstream`. The reference code is random; never echo the exception message or a stack trace.
2. **Toasts:** one `toast(kind, message, action)` helper in `app.js`; success and information close after 4 s, errors persist until closed; stack; Undo variant exists as a component but no route needs it yet. Existing headers drive it. Test the headers still work.
3. **Swap behaviour:** `.skel` after 300 ms, `htmx:responseError` / `htmx:sendError` put an `.alert` in the target (never blank), `.htmx-swapping` / `.swap-in`, `.btn.loading`. One global script, no per-template code.
4. **Modals and menus:** implement the behaviour the mockups specify (Esc closes, focus returns to the trigger, scroll lock, typed-name confirmation for delete/purge) as components and wire them to the existing destructive routes only where a template already has a confirm (`hx-confirm` or a purge page). Do not add routes. If a mockup modal has no route (`invite`, `send`), build the component and a `/design` specimen only.
5. **Allow-list:** prune stale entries; convert the residual Tailwind classes in the ~12 templates above to Yozora classes (mechanical, behaviour-preserving, no restyling beyond that); the allow-list file is deleted only if every non-print template then passes the lint. If a template cannot be converted without a redesign, leave it listed and report it; do not force it.
6. **Tailwind retirement:** remove `tailwind.css` and `style.css` links, `tailwind.config.js` and the npm scripts only if a scan proves zero remaining users outside print templates, and print templates do not load them. Otherwise keep the build and list the users. Never edit the print templates.
7. **Dark and mobile pass:** one gate run of every migrated screen at the widths it uses, both themes, reported as a table (screens, states, themes, widths, number over threshold) with exceptions classed by cause. The brief's "must be zero failing" is replaced by: **no state that is broken** (horizontal overflow at 390, clipped controls, invisible text in dark, more than one visible primary). Percentage misses with a content or height cause are exceptions.
8. **Seed:** `design/harness/seed_s9.py` reusing the S3 to S8 builders (never edit another slice's seed). Error pages and system components render through `design_s9_*` preview routes like earlier slices.
