## Goal

Audit finding F-A16 (`tasks/2026-10-13-content-audit.html`, search F-A16; plan row 2.8 in `docs/plans/2026-10-13-001-single-track-implementation-plan.md`, about line 219).

- **Reject needs a reason.** Today a reviewer can reject a conclusion with no reason, and no reason is stored anywhere. After this WP, a reject without a non-blank reason is refused with a visible error and nothing is saved. The reason is stored and shown.
- **Undo.** A reviewer can undo an approve, edit or reject. Undo returns the conclusion to pending review, records who and when, and keeps history.
- **Reviewer name defaults from Settings.** A new firm setting holds the default reviewer name. Review screens prefill it; the reviewer can still type a different name.

Note on plan assumption A7: the plan said the old Jinja form could send "Not stated" as a stopgap. Saqlain decided against it (14 Oct). The Jinja card gets a real reason box instead. "Not stated" must not appear anywhere in app code.

## Decisions (confirmed by Saqlain, 14 Oct)

| # | Decision | Value |
|---|---|---|
| D1 | Reject form | A required reason text box beside Reject on the conclusion card. Blank or whitespace-only reason: HTTP 400, error text exactly `Give a reason for rejecting this conclusion.`, shown the same way other decision errors are (the existing `InvalidDecision` path: JSON `detail` plus `X-Toast-Message` / `X-Toast-Type: error`), and nothing is saved (no revision, no version bump). |
| D2 | Undo only before release | Undo is refused when the assessment's report is currently released (`approved_report.is_released(db, assessment)` is true). Error text exactly `This report is released. Undo is not available.` (400, same error path). Reject and reopen keep today's behavior after release (they mark the release stale); only Undo is guarded. |
| D3 | Undo target | Undo of an approve, edit or reject returns the conclusion to `pending`. The current conclusion text is not rolled back (same as reopen today: an edit's changed wording stays). History is append-only: undo adds a revision; nothing is deleted or rewritten. Undo is not offered on `pending` (nothing to undo). |
| D4 | Reviewer name | New nullable firm setting `default_reviewer_name` (max 200 chars, stripped, blank stored as NULL). Prefill order on review screens: Settings value, else today's "latest name used on this assessment", else blank. The box stays editable. A blank submitted name falls back to the Settings value, then to `Manager Review` (`DEFAULT_REVIEWER_NAME`) as today. |

## Design

- **Storage.** One new Alembic revision after `e2c8f6a4d901` adds `conclusion_revisions.reason` (Text, nullable) and `firm_settings.default_reviewer_name` (String(200), nullable). No backfill (historical rejects have no reason; display handles NULL). Historical revisions are never edited.
- **Reject.** `ConclusionDecisionIn` gains `reason: str = ""` (max 2000). In `decide()`, when the action is `rejected` and `reason.strip()` is empty, raise `InvalidDecision` with the D1 text before any write. Store the stripped reason on the new revision. Other actions ignore `reason`, except undo (below).
- **Undo.** New route `POST /api/assessments/{id}/conclusions/{conclusion_id}/undo`, `ACTION_BY_ROUTE["undo"] = "undone"`. Add `"undone"` to `HUMAN_DECISION_ACTIONS` (non-locking, so the derived state is `pending`, exactly like `reopened`). `ALLOWED_ACTIONS`: `"undone"` allowed from `approved`, `edited`, `rejected`. The D2 release guard runs in `decide()` for undo only. Same CAS on `expected_version`, same 409 conflict behavior. Success message `Decision undone`. The revision records `actor` and `created_at` as other decisions do; set `reason` to `Undid <previous action>` so the history line says what was undone.
- **Labels.** Add `undone` wherever decision actions are labelled: `app/services/workpaper.py` `ACTION_LABELS` ("Undone"), the card's decision labels, and the card footer for a rejected conclusion shows the reason: `Rejected by X on date: "<reason>". It is left out of the report until approved.` (no quote part when reason is NULL). Escape normally (Jinja autoescape).
- **Card UI.** Reject form adds `<input name="reason" ... required maxlength="2000">` (or a one-line textarea) with a visible label "Reason for rejecting". Add an Undo button (`btn ghost`) when `"undone"` is in `card.allowed_actions` and the report is not released. Keep Reopen as is.
- **Reviewer name.** One helper, `default_reviewer_name(db, assessment_id) -> str`, in `app/services/conclusion_review.py` implementing the D4 prefill order. The three `_latest_reviewer_name` definitions call it (keep their names so importers do not change). `reviewer_actor` gains the Settings fallback: pass the Settings value in from callers that have a db, or add `reviewer_actor_for(db, name)`; keep `reviewer_actor(name)` working unchanged for existing callers. Settings form gets a "Default reviewer name" field; `validate()`/`update()`/`FirmSettingsView` carry it, and the change is audited by the existing `firm_settings.updated` event.
