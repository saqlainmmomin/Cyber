# P6-8 B2: DOCX + XLSX deliverables derived from the board report snapshot `[AR: write-once + derived-only + formula injection]`

Consultants and client teams get an editable Word version of the board report and an Excel workbook (requirement register, top risks, action tracker, evidence register). Both are derived **only** from a `board_report` version's stored, hash-checked JSON sidecar (B1, PR #80). They are rendered on request, never stored, byte-deterministic, and never touch the live database beyond loading the snapshot row and its generated audit event.

**Plan:** `docs/plans/2026-09-25-001-grounded-analysis-and-deliverables-plan.md`, Track 2 P6-8, Part D (D2 content, D3 formats, D4 rendering) and Part F (D-P6-H). B1 design + sketch: `tasks/handoffs/2026-09-28-p6-8-board-report-v2.md` ("B2 sketch"). House rules: only approved data reaches client outputs (inherited: the sidecar is built from approved data only); deterministic fields never come from an LLM; framework-specific copy is conditional (B2 adds no framework copy of its own); snapshots are write-once.
**Owner:** Claude designs (this file + contract tests) → Codex implements → Claude adversarial review → PR. Per `tasks/agent-ownership.md`, Phase 6 row "P6-6..P6-10 Deliverables".
**Branch:** `claude/p6-8-b2-docx-xlsx` from `origin/main` @ `4f5309d`. The designer's commit sits on top.

## Goal

1. `GET /api/assessments/{aid}/snapshots/{sid}/docx` and `…/xlsx` return a DOCX / XLSX for any `board_report` version, rendered from `read_board_report_document(db, snapshot)` only.
2. Same document + same code = same bytes, whatever the wall clock.
3. The versions page shows "DOCX" and "XLSX" links on each board report row.
4. Devanagari and ₹ round-trip exactly (DOCX and XLSX store text, not glyphs).
5. No formula can execute from any cell; XML-illegal control characters never crash an export.

## Current state (origin/main @ 4f5309d)

- `board_report` versions store `{sid}.pdf` + `{sid}.json` (canonical JSON, `document_sha256` in the generated audit event). `report_snapshots.read_board_report_document` returns the dict or raises `SnapshotNotFound` (wrong type, 404) / `SnapshotIntegrityError` (missing, hash mismatch, bad JSON, 500 with `INTEGRITY_MESSAGE`).
- The document (schema v1) already carries everything B2 needs: `snapshot.id`, `snapshot.version_label` ("v<N>"), `snapshot.generated_at`, `company_name`, `firm_name`, frameworks, basis labels, summary, top risks, roadmap, register, evidence register. So B2 needs no `snapshot_rows` / sequence lookup.
- RFI precedent: `rfi_version_docx` renders DOCX on request from the RFI sidecar; `rfi_export._stamp_zip_entries` pins zip timestamps (`tests/test_rfi_docx_determinism.py`).
- `python-docx==1.1.2` is pinned; **openpyxl is not installed** anywhere.
- `app.utils.http_headers.attachment_disposition` gives an ASCII fallback plus `filename*=UTF-8''…`.

## Decisions

### D-P6-8-B2-A: Derived artefacts, not snapshot types; rendered on request, never stored
- DOCX/XLSX are **not** new snapshot types and write **no** file, row or audit event. The authoritative, write-once artefact stays the board PDF + sidecar; the exports are a pure function of that sidecar.
- Why: storing would need new write-once plumbing, new metadata keys (B1 scenario 8 pins them exactly) and would not exist for already-generated versions. The RFI DOCX precedent is the same.
- Consequence: if exporter code changes later, a re-download of an old version can differ. That is accepted and made visible: every export carries `EXPORT_FORMAT_VERSION` (About sheet, response header). See Open question 1.
- No release gate on download (like the `/file` route): an existing version stays downloadable after the assessment is reopened.

### D-P6-8-B2-B: Inputs
The route may read exactly: `load_snapshot`, `read_board_report_document`, `generated_event(...)["document_sha256"]`. Nothing else from the DB. `board_exports.py` itself has no DB access at all (scenario 10 bans `Session`, `app.models`, `build_document`, `approved_report`, `report_content`, `report_basis`, `conclusion_review`, `workpaper`, and LLM tokens from its source). Filename, labels and all content come from the document (so renaming the client after generation changes nothing, scenario 4).

### D-P6-8-B2-C: Module `app/services/board_exports.py` (new)
```python
EXPORT_FORMAT_VERSION = 1
SUPPORTED_SCHEMA_VERSIONS = (1,)
DOCX_MEDIA_TYPE = "application/vnd.openxmlformats-officedocument.wordprocessingml.document"
XLSX_MEDIA_TYPE = "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"
DERIVATION_LABEL = ("Derived from board report snapshot {snapshot_id8}, {version_label} (document SHA-256 "
                    "{sha_prefix}). Edits to this file do not change the report version it was derived from.")
UNSUPPORTED_DOCUMENT_MESSAGE = ("This report version's document format cannot be exported to DOCX or XLSX "
                                "by this version of CyberAssess. The report version is unchanged.")
DOCX_BODY_FONT = "Noto Sans"
DOCX_COMPLEX_SCRIPT_FONT = "Noto Sans Devanagari"
FORMULA_PREFIXES = ("=", "+", "-", "@", "\t", "\r")
XLSX_SHEETS = ("About", "Framework summary", "Requirement register", "Top risks", "Action tracker", "Evidence register")
XLSX_COLUMNS = {...}        # exactly as in the test file
DOCX_TABLE_HEADERS = {...}  # exactly as in the test file (same headers as the PDF template)

class UnsupportedDocument(report_snapshots.SnapshotError): status_code = 409

def derivation_label(document: dict, document_sha256: str) -> str   # sha_prefix = sha[:board_report.SHA_PREFIX_CHARS]
def export_filename(document: dict, extension: str) -> str          # f"{company_name}_board_report_{version_label}_{id[:8]}.{ext}"
def render_docx(document: dict, *, document_sha256: str) -> bytes
def render_xlsx(document: dict, *, document_sha256: str) -> bytes
```
- Both renderers first check `document["schema_version"] in SUPPORTED_SCHEMA_VERSIONS`, else raise `UnsupportedDocument(UNSUPPORTED_DOCUMENT_MESSAGE)`. A later schema bump (P6-9/P6-10) must **add** its version and keep v1 working; old sidecars are v1 forever.
- Import `openpyxl` and `docx` **inside** the render functions (scenario 10 rejects a top-level `openpyxl` import), so the app starts even if openpyxl is missing.
- May import `display_date` and `SHA_PREFIX_CHARS` from `app.services.board_report` (read-only; do not edit that module).
- One private `_clean(text)` strips XML-illegal characters `[\x00-\x08\x0b\x0c\x0e-\x1f]` from every string written to either format (python-docx raises `ValueError`, openpyxl `IllegalCharacterError` otherwise). `None` renders as `""` in DOCX and as an empty cell in XLSX (never the string "None").

### D-P6-8-B2-D: DOCX content (mirrors the PDF template `reports/board_report.html`)
- `Normal` style: `font.name = DOCX_BODY_FONT`, and `rPr/rFonts` `w:cs = DOCX_COMPLEX_SCRIPT_FONT` (Word shapes Devanagari with the complex-script font; Windows falls back to Nirmala UI/Mangal if Noto is absent). No embedded fonts.
- Body order, strings identical to the PDF template where the PDF has them:
  1. Paragraph: the derivation label (small italic). It must precede "Management summary" and appear exactly once.
  2. Cover: `Title` "Board report"; company name; engagement (if any); `Frameworks: name (version), …`; `Assessment period: {period_label} | Evidence cut-off: {cutoff_label}`; `Report generated: {generated_on}`; `Version {vN} | Snapshot {id8}`; release line if `released_by`; `issue_status`. Page break.
  3. `Heading 1` sections in this exact order: "Management summary", "Top risks", "Remediation roadmap", "What we could not assess", one per framework section `"{name} ({version})"`, "Sign-off", "Appendix A: Methodology", "Appendix B: Requirement register", "Appendix C: Evidence register". Subsections (`Basis of assessment`, `Scope`, `Limitations`, `Confidentiality`, `Scores and coverage`, `Insufficient evidence`, `Request for information`, `Domains`, `Gaps`) are `Heading 2`.
  4. Top risks: each risk is a `Heading 2` `"{rank}. {title}"`, then description paragraph, the meta line, one paragraph per citation `"{filename} v{n}, {location_ref} (SHA-256 {prefix})"`, the owner/target line and the action line, as in the PDF. Empty: "No approved findings are recorded."
  5. Tables with `DOCX_TABLE_HEADERS` as the header row: scores (under Scores and coverage), roadmap, one domains table and (when gaps exist) one gaps table per framework, requirement register, evidence register. Cell text rules = PDF rules (dates via `display_date`, "Not recorded"/"No target date"/"Unassigned" fallbacks, `v{n}`, "Yes"/"No", `citation or citation_note`, closes joined with "; ").
  6. Empty-state sentences as in the PDF.
- Header `"{firm_name} | Board report"`, footer `"{company_name} | {version_label}"`.
- Core properties: `title = f"Board report: {company_name}"`, `author = last_modified_by = firm_name`, `comments = label`, `identifier = snapshot.id`, `subject = f"Board report {version_label}"`, `revision = 1`, `created = modified = generated_at` (UTC, naive). Do not set `last_printed`.
- B2 adds no copy of its own beyond the label and headings; everything framework-specific comes from the (already conditional) document. Scenario 9 checks an ISO-only export.

| Action tracker | one per roadmap action: title, owner, target_date (date cell), status_label, then `closes` framework names / requirement ids / finding titles each joined "; " (one row per action, so P6-9's multi-close actions stay one row), then two empty client columns "Client update", "Evidence of closure" |

- Dates: `datetime.date` values with `number_format = "yyyy-mm-dd"`.
- Workbook properties: `creator = lastModifiedBy = firm_name`, `title = f"Board report: {company_name}"`, `description = label`, `identifier = snapshot id`, `created = modified = generated_at` (UTC, naive).
- Devanagari/₹: plain Unicode strings; nothing special is needed (openpyxl writes them as character references; they read back exactly).

### D-P6-8-B2-F: Determinism
- A private `_pin_package(content: bytes, generated_at: datetime) -> bytes` used by both formats: rewrite every zip entry in order with `ZipInfo(name, date_time=generated_at.timetuple()[:6])`, `ZIP_DEFLATED`, same `external_attr`; for `docProps/core.xml` replace the text of `<dcterms:created …>` and `<dcterms:modified …>` with `generated_at.strftime("%Y-%m-%dT%H:%M:%SZ")`.
- Why the core.xml rewrite: probed openpyxl 3.1.5 **overwrites `modified` with now() on save**, even when set. python-docx stamps zip members with the wall clock (the P5-6 flake). Do not edit or import `rfi_export._stamp_zip_entries` (rfi_export.py is frozen, and it does not fix core.xml).
- `generated_at` = `datetime.fromisoformat(document["snapshot"]["generated_at"])` converted to UTC, tzinfo dropped.

### D-P6-8-B2-G: Routes and the versions page
In `app/routers/snapshots.py`, append:
```python
@router.get("/{assessment_id}/snapshots/{snapshot_id}/docx")
@router.get("/{assessment_id}/snapshots/{snapshot_id}/xlsx")
```
sharing one helper:
1. `db.get(Assessment, aid)` is None → `_error(404, "Assessment not found")`.
2. In one `try`: `load_snapshot` (404 for another assessment's id), `read_board_report_document` (404 wrong type, 500 integrity), `generated_event(db, sid)["document_sha256"]`, then the renderer (409 `UnsupportedDocument`). `except report_snapshots.SnapshotError` → `db.rollback()`, `_error(exc.status_code, exc.message)`.
3. `db.rollback()` (read-only), then `Response(content, media_type=…, headers={"Content-Disposition": attachment_disposition(export_filename(document, fmt)), "X-Board-Document-Sha256": sha, "X-Board-Export-Format-Version": "1"})`.

No POST, no write, no audit event, no `.unlink(` or `.commit(` added to the router.

`app/templates/pages/report_snapshots.html`: in the File cell, after the existing Download link, when `type == 'board_report'`, add `<a data-board-export="docx" href="/api/assessments/{{ assessment.id }}/snapshots/{{ row.snapshot.id }}/docx" …>DOCX</a>` and the same for `xlsx`, styled like the Download link. Nothing on other rows.

### D-P6-8-B2-H: Formula injection (OWASP) and illegal characters
- Any XLSX string cell whose value starts with one of `FORMULA_PREFIXES` is written with `cell.data_type = "s"` **and** `cell.quotePrefix = True` (Excel's native "this is text" flag, the hidden apostrophe). The visible text is unchanged; no `<f>` element can ever be written. Other string cells do not get `quotePrefix`. Every string cell is set with `data_type = "s"` after assignment (openpyxl otherwise turns `"=…"` into a formula, probed).
- This deliberately refines the B1 sketch's "prefix a visible `'`" (Open question 3).
- DOCX has no formulas; text is written as-is after `_clean`.

## Adversarial review checkpoints `[AR]`

1. **Derived-only:** does the route or exporter read anything but the snapshot row, its generated event and the sidecar? Is the sidecar hash-checked before parsing (via `read_board_report_document`, never a direct file read)?

5. **Schema:** unknown schema refused in both renderers before any output.
6. **File set** matches the table exactly.

## Open questions for Saqlain (each has a default; nothing blocks B2)

1. **Freeze exports at issue time?** Exports are re-rendered on each download, so an exporter change could alter an old version's DOCX. **Default:** accept it (the PDF + sidecar are the record; exports carry `EXPORT_FORMAT_VERSION`). Alternative: when a board report is issued, also store its DOCX/XLSX write-once with hashes in the issued event (a later task; needs new event metadata).
2. **Findings sheet only has the top 10.** The v1 document stores `top_risks` (capped at 10), not every approved Finding. **Default:** the sheet is named "Top risks" honestly; the full gap list is in "Requirement register" and every Finding with an Action is in "Action tracker". Alternative: P6-9 adds a full `findings_register` to the document (schema v2) and B2 grows a "Findings" sheet then.
3. **Formula-injection style.** **Default:** Excel's `quotePrefix` flag (text shows as written, never evaluated in Excel). The OWASP CSV advice of a visible leading `'` protects a later CSV re-export too, but makes ordinary text like "- no policy" display as "'- no policy". Say if you prefer the visible apostrophe.
4. **Client edits coming back.** The tracker's "Client update" / "Evidence of closure" columns are for the client. **Default:** no import in B2; consultants re-key updates into Actions. An XLSX import of those two columns would be a separate, reviewed task.
