| UC-NET-01 | **Endpoint device protection**<br>Security requirements for user endpoint devices, such as registration, encryption, screen lock, patching, anti-malware and remote wipe, are set and extended to personally owned devices where those are allowed. Device management tools check devices against the requirements continuously, and non-compliant devices are fixed or cut off from company data. This keeps lost, stolen or poorly maintained devices from exposing company data. Proof is the endpoint policy and the device compliance report. | Head of IT Operations<br>high<br>Technological | Read the endpoint policy and confirm it sets minimum settings, including for personal devices if allowed. Cover the last audit period. | ISO: A.8.1 (full) |  | [x] |
| UC-NET-02 | **Secure configuration baselines**<br>A secure configuration baseline is documented for each type of operating system, database, cloud account and network device in scope. Compliance scans or configuration monitoring compare live systems with the baselines, and drift is fixed. Each baseline is reviewed on its own defined cycle, and the version history shows it. This reduces weaknesses from default or drifting settings. | Head of IT Operations<br>high<br>Technological | List the in-scope technology types and confirm each has a baseline. Sample systems and check the latest compliance scan results against the baseline, then trace drift findings to fixes. Pass if every type has a baseline, sampled systems are scanned, drift is remediated, and each baseline was reviewed within its stated interval. | Configuration baselines per technology type with version history; compliance scan or configuration monitoring reports; drift remediation tickets; hardening standard. Cover the last two review cycles. | ISO: A.8.9 (full)<br>NIST: DE.CM-09-c (full); ID.AM-08-b (full); PR.PS-01-a,b,c (full) |  | [x] |
| UC-NET-03 | **Network security management**<br>A network security standard is set and maintained, covering how networks and network devices are secured and managed, including device hardening, administrator access and encryption in transit. A current network diagram of the in-scope environment is kept, including cloud networks and links to third parties. Firewall and security group rules are reviewed on a defined cycle, and unneeded or overly permissive rules are removed. This limits the paths an attacker can use. Proof is the standard, the diagram and the rule review records. | Network and Infrastructure Lead<br>critical<br>Technological | Check the diagram's last update date and compare it with a sample of live network components or cloud networks. Inspect the latest firewall and security group review record and trace sampled removals to change tickets. Pass if the diagram is current and complete, the standard exists, and a review happened in the period with permissive rules removed. | Network security standard; current network diagram including cloud and third-party connections; firewall and security group rule review records with removals; change tickets for rule removals. Cover the last two review cycles. | ISO: A.8.20 (full)<br>NIST: ID.AM-03-a,c (full); PR.IR-01-a,d (full); PR.PS-01-d (full) |  | [x] |
| UC-NET-04 | **Security of network services**<br>The security features, service levels and requirements of each network service the organization uses, such as internet links, DNS, VPN, content delivery and managed connectivity, are documented. This keeps the organization from depending on network services that do not meet its needs. Proof is the service agreements and the review records. | Network and Infrastructure Lead<br>high<br>Technological | List the network services in use and sample some of them. For each, check the documented requirements and the latest service level report. Pass if requirements are documented, external ones are in contracts, and reports were reviewed against the agreed levels in the period. | List of network services and providers; service agreements stating security features and service levels; service level reports with review sign-off. Cover the last two review cycles. | ISO: A.8.21 (full) |  | [x] |
| UC-NET-05 | **Network segregation**<br>Network segments are defined by trust level or function, such as production, development, corporate, guest and management, and the traffic allowed between them is stated. The design is enforced through firewall, VLAN or security group settings. Configuration exports show the enforcement. This limits how far an intruder can move from one compromised system. | Network and Infrastructure Lead<br>high<br>Technological | Pick sample segment boundaries from the design, such as guest to production and development to production. Inspect the configuration export for each. Pass if the configured rules enforce the documented allowed traffic and block the rest. | Segmentation standard and network diagram showing segments and allowed flows; firewall, VLAN or security group configuration export for sampled segments.
